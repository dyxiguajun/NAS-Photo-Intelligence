# NAS Photo Intelligence Engine — Phase 1 验收报告

日期：2026-10-15，America/Los_Angeles。

## 结论

Phase 1 命令行 MVP 已实现，并完成原有 15 个 NAS 样本的元数据索引与增量验证。SQLite、原始证据、异常标签、任务恢复、错误记录和报告导出均有实际执行证据。没有进入 Phase 2，没有扩大 NAS 样本范围。

## 连接与范围

已确认挂载表为 `<NAS_USER>@<TAILSCALE_NAS_IP>`，共享实际挂载在 `/Volumes/<NAS_SHARE>`。检查了此前的恢复目录、DICM、OneDrive 图片、独立手机备份目录，每个仅列出首个条目；读取了一个已知样本的 16 字节文件头验证实际可读。

索引只使用 `config/phase0_samples.json` 的 15 项，与 Phase 0 文件集合相同。没有调用 NAS 目录发现、递归全库扫描、哈希、批量图像解码或额外选样。工具仅本地读取元数据和一个 MOV 的媒体信息。

## 已实现

- Python 标准库 CLI、固定版本官方 ExifTool 13.59、现有 file / ffprobe。
- 五个独立来源；逻辑身份与 IP、挂载根分离。文件唯一身份是 `(source_id, relative_path)`。
- 本地 SQLite，外键、WAL、FULL 同步、单写入者锁；schema version 1。
- 原始时间字符串、纳秒修改时间、异常创建时间、解析状态、时区、相机、镜头、尺寸、方向、真实格式与工具证据。
- 原始观察历史与最新索引分别保存。GPS 默认仅持久保存存在布尔值；没有写入个人坐标。
- 内容信息、元数据完整度、时间可靠性与来源信任分开记录，没有综合质量分数或自动选定“正确日期”。
- 八类时间/元数据/格式标签及可解释理由，支持不读取照片的标签重算。
- 持久化任务与逐文件提交、有限重试、整个文件 I/O 超时、取消、强制退出后续跑、增量跳过。
- 受限目录发现及诊断导出；本轮仅在本地临时模拟数据测试该功能。
- JSON 摘要、JSONL 逐文件证据、CSV 报告、JSONL 事件日志。
- 一个同 stem 图片/MOV 配套候选，保持未验证状态，不视为重复。

## 异常标签统计

标签可重叠，以下是文件数，不应相加作为异常文件总数。

| 标签 | 数量 | 解释 |
|---|---:|---|
| early_filesystem_timestamp | 2 | 恢复 JPEG/PNG 的文件修改时间早于筛查线 |
| invalid_timestamp | 2 | 相同两文件的 SMB 创建时间超出可表示范围，原始值保留 |
| missing_capture_time | 5 | 没有解析到原始拍摄/视频容器时间候选 |
| timestamp_conflict | 2 | 恢复样本 16 小时差、OneDrive 内部日期与文件日期差异；未判定哪项错误 |
| timezone_uncertain | 3 | 两张 PNG 与一张历史照片的候选时间没有明确偏移 |
| metadata_incomplete | 8 | 按本版规则缺少时间候选或图片相机型号，不代表内容质量差 |
| format_identification_conflict | 2 | 保留 S10/S11 的 Phase 0 ImageIO 历史分歧；当前文件头、file、ExifTool 均为 JPEG |
| future_timestamp | 0 | 这 15 个真实样本未触发，未来日期的正例在自动测试中验证 |

默认早期筛查线为 `2000-01-01`，本机冲突容忍为 12 小时，未来容忍为 30 天。时间无明确偏移时不强制转换 UTC，也不作绝对秒差判断。早于 2000 年仅作为可疑条件，真实 1998 年照片的测试不会被认定为无效。

ExifTool 在 S10/S11 中读到了 Phase 0 ImageIO 未提供的 `-08:00` 偏移；这是提取证据补全，没有写入照片或覆盖 Phase 0 原报告。OneDrive 的 2021 年内部时间仍保留，2024 年文件时间仅作为另一证据。

## 自动测试与故障验证

最终自动测试：**31 项通过，0 失败，0 跳过，7.482 秒**。完整日志 `reports/unit-tests.log`，编译检查通过。

覆盖：

- 时间溢出、非有限 epoch、无效日历及偏移、未知时区、未来日期、可配置筛查线。
- 真实早期日期不直接判错；复制/导出导致的日期差异不会产生自动修复决定。
- 增量跳过，单文件修改后仅重新提取该文件。
- 同一来源切换挂载路径，仍保留同一个文件身份。
- 模拟挂载路径失效，两次失败记录持久化，恢复路径后显式重试成功，旧元数据不丢失。
- 单个坏文件不会阻塞其他文件，慢工具超时在限定时间内结束。
- 强制杀掉扫描主进程，保留已提交第一条；恢复同一任务后仅补齐未完成项。
- 注入安全取消，保留待处理队列并成功续跑。
- 重复中断耗尽重试预算后停止，需显式 retry-failed 开放新预算。
- 路径逃逸、符号链接、重复来源、来源 ID 被重新指向其他逻辑目录、输出与输入重叠、网络卷输出被拒绝。
- 工作进程拒绝在共享进程组中单独启动，避免误伤其他程序。
- 有限发现的目录条目/文件上限、标签重算不读取照片、导出字段及计数。
- 官方 ExifTool 对本地微型 PNG 的实际读取，临时测试文件内容保持相同。

挂载失效和路径迁移使用本地临时路径模拟，没有主动断开真实 SMB/Tailscale。没有真实重启 Mac、做整夜运行或在 NAS 本机运行；强制终止测试证明的是持久队列恢复，不替代所有机器故障验收。

## 已知边界与下一阶段

- 未实现 SHA-256、感知哈希、相似检索、版本判断、删除/修复建议或任何照片写操作。
- 增量使用大小与文件时间，无法检测刻意保留大小/时间的内容替换，也不自动识别来源内部重命名。
- 只提取固定的有用标签，不是完整 EXIF/XMP/MakerNotes 取证。未知时区保持未知；没有设备年代数据库或复杂可信度评分。
- 格式识别、读取成功不代表所有像素/视频帧完整。PNG/HEIC 仅提取元数据，没有做全图解码。
- 发现操作输出受限 manifest；持久断点恢复针对已建立的索引任务，而不是全库目录遍历游标。
- 配套候选尚未验证内容标识，不能作为自动清理依据。
- 本轮 macOS 实测通过，不代表 NAS/Linux/Windows 已部署可用；未登录 NAS 管理、创建容器或修改 SSH 验证。

Phase 1 完成后停止。未来由用户决定是否进入 Phase 2；没有自动开启全量扫描、整夜任务或定时任务。
