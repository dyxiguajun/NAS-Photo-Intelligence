# 04 感知哈希的误报率与漏报率实测

## 4.1 分层定义

| 层 | 判据 | 性质 |
|---|---|---|
| **L0** | 全文件 SHA-256 完全相同 | **证据**：字节级相同 |
| **L1** | 解码后像素完全相同 | **证据**：内容相同 |
| **L2** | 感知哈希距离在阈值内 | **候选**，不是证据 |

本文所有结论都是关于 **L2**。

## 4.2 哈希参数

```python
phash = imagehash.phash(img, hash_size=8, highfreq_factor=4)   # 64 bit
dhash = imagehash.dhash(img, hash_size=8)                       # 64 bit
distance = 汉明距离（0..64）
```

## 4.3 误报率（FPR）

**样本**：111 个分层抽样的切出对象，用**多尺度归一化互相关（NCC）**做真值判定。
NCC ≥ 0.90 判为同内容。

| pHash 距离 | 误报率 | 中位 NCC |
|---|---:|---:|
| **0** | **2.5%** | 1.000 |
| 1–4 | 62.5% | — |
| 5–8 | **100%** | — |
| 9–12 | **100%** | — |
| 13–16 | **100%** | — |

### 关键结论

- **距离 = 0 可用**：97.5% 的 d=0 配对是真正同内容
- **距离 ≥ 5 永远不能作为重复证据**：误报率 100%
- 距离 1–4 误报率 62.5%，**不可单独使用**

### 这意味着什么

如果拿 pHash ≤16 当"重复"依据，误报率接近 100%——
即几乎每一对"匹配"都不是同一个文件。

所以 pHash 的**唯一合法用途**是
**从海量数据里筛出候选，然后用 L0/L1 验证**。

## 4.4 漏报率（FNR）

**样本**：42 对确认为真正相同的图像对。

| 阈值 | 漏报率 |
|---|---:|
| 距离 = 0 | **7.1%** |
| 距离 ≤ 4 | **0%** |

### 结论

- 只看 `d=0` 会漏掉 7.1% 的真同内容
- **`d ≤ 4` 能覆盖全部 42 对真样本**
- 但 4.3 节说 `d=1..4` 误报率 62.5%

**这两条同时成立**说明：
`d ≤ 4` 是"高召回、低精度"的候选窗，必须配验证，不能单独定论。

## 4.5 负例集实测

**构造方式**（152 对确定性负例）：
同目录 + 同相机 + EXIF 时间差 ≤ 2 秒 + 文件名不同。

| pHash 距离 | 误报率 |
|---|---:|
| 0 | 0.7% |
| 1–3 | 5.9% |
| 4–10 | 17.8% |
| 双条件 pHash≤10 且 dHash≤12 | 15.1% |

### 为什么这个负例集不可靠

有 **562 对同文件名**的样本被排除，因为这些样本里同时出现了
`NCC = 1.0000` 和 `NCC = 0.1219` 的配对——
说明**文件名相同完全可能是两个不同事件**，
文件名不同也**不能**证明是负例。

所以：**"同目录 + 同相机 + 时间邻近 + 不同文件名"不能定义负例。**
真正的负例需要独立标注。

## 4.6 像素级验证方法

对 pHash 候选对，做多尺度 NCC：

```
把两张图都转灰度，缩放到 16 / 32 / 64 / 128 四个尺度
逐尺度计算归一化互相关
任一尺度 NCC ≥ 0.90  →  判为同内容
```

用多尺度是为了同时覆盖"同一张图不同尺寸"和"同一张图不同裁剪"。

## 4.8 性能数据

| 格式 | `draft()` 是否有效 | 单文件耗时 |
|---|---|---|
| JPEG | ✅ 有效 | 约 0.01 s |
| PNG | 部分有效 | 约 0.05 s |
| **HEIC** | ❌ **无效，必须全解码** | **约 0.30 s** |

HEIC 的 `draft()` 调用**完全不起作用**，必须全量解码。

### `draft()` 的语义陷阱

`draft("L", (64,64))` 返回的是**按 1/2、1/4 或 1/8 缩小后的尺寸**，
不是请求的 64×64。

例如一张 3024×4032 的图，`draft()` 后可能变成 240×320。
**因此 `im.size` 在这之后已经不是原始尺寸**
——真实尺寸必须单独记录。

这就是为什么索引记录里同时有：
- `w`/`h`：哈希计算时用的尺寸（可能是缩小后的）
- `real_w`/`real_h`：原始真实尺寸

## 4.9 一条硬规则

> **距离 5 以上的 pHash 匹配，不得作为任何重复判定的证据。**

这条规则的依据是 4.3 节的 100% 误报率实测。
任何绕过这条规则的处理，都必须先给出新的实测数据。
