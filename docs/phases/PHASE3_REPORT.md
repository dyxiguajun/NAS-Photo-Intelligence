## 交付能力

- L0：保留 Phase 2 的完整 SHA-256 证据和重复组，可为当前有效的相同字节成员复用代表图像指纹。
- L1：完整规范化 RGBA8 像素 SHA-256，定义方向、ICC/sRGB、Alpha、解码器和算法版本；不以缩略图冒充完整像素。
- L2：ImageHash 64 bit pHash + dHash；有限直角旋转、长宽比/颜色/低信息量辅助筛查，保存成对候选、原始距离及阈值，不建立传递相同组。
- 持久 visual 任务、逐文件提交、有限重试、取消/强杀恢复、读入计数与保守预算、有效缓存、文件/哈希/版本变化后的关系失效。
- 单图隔离进程、像素门限、工作集估计、RSS 采样和超时保护。默认单线程解码，没有视觉模型依赖。
- 兼容 schema 3 迁移及 JSON/JSONL/CSV 报告，原 CLI 保留。

库选型与官方依据见 `docs/PHASE3_LIBRARY_REVIEW.md`，具体规范化、表结构及边界见 `docs/ARCHITECTURE.md`。

## 当前局限与下一步边界

L1 是指定规则下像素一致，不保证跨任意解码器一致。stat 缓存无法绝对排除隐蔽替换；compare/report 反映记录时的状态，不实时读 NAS。RSS 采用估计加采样，不能代替 OS 硬沙盒。HDR/高位深、多帧 JPEG/PNG、复杂裁剪/滤镜/文字编辑、任意角度旋转、语义相似均不在已验证保证范围内。HEIF 只分析主图；Live Photo 仍是配套候选。小样本不能证明全库准确率或预测全库耗时。

没有选择“最佳原图”、质量评分、恢复版本排序、自动删除或 Phase 4 开发。程序可独立解码和比较，无需模型逐张参与。Progress App 一直保持运行；最后保存的 300 分钟窗口剩余约 54%，该值仅为记录时快照，后续须查实时值。
